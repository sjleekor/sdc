## 3. `00_overview.md` §1.1 — interaction ≡ 조건부 IC

### 3.1 항등식 — 맞다

`_spearman`(`metrics.py:424`)은 평균 순위(`_rankdata`) 위의 Pearson 상관이다. 날짜 안에서 `x`에 상수 `s_t`를 곱하면

- `s_t > 0`: 순위 불변 → IC 동일
- `s_t < 0`: 순위가 `r → n+1−r`로 뒤집힘. 동점은 동점으로 남고 평균 순위도 대칭이라 상관은 **정확히** 부호만 바뀐다
- `s_t = 0`: 피쳐가 상수 → `ps == 0` → NaN → `scan_cell`이 `market_ic.filter(rank_ic.is_finite())`로 그 (날짜, 시장)을 버린다

`polars_native_v1` 경로(`pl.corr(method="spearman")`)도 평균 순위를 쓰므로 같다. 따라서 `s_t ≠ 0`인 날에 `IC_t(s·x) = sign(s_t)·IC_t(x)`는 맞다. `q5_spread`도 분위가 뒤집혀 부호만 바뀐다.

### 3.2 평균 IC 공식 — 틀리다 (코딩 조건이 빠졌다)

문서 공식 `P(s>0)·E[IC|s>0] − P(s<0)·E[IC|s<0]`는 `s ∈ {−1, +1}` 코딩에서 성립한다. `03` §2가 정의한 국면은
`s_t = 1[z_t > 0] ∈ {0, 1}`이다. 이 코딩에서 interaction family를 스캔하면 `s=0`인 날이 전부 탈락해

```
ic_mean(s·x) = E[IC | s = 1],   n_dates = #{s = 1}
```

이 된다. 즉 "국면 점유율 × 무조건부 IC"가 아니라 **한쪽 조건부 평균**이다. 부호 코딩으로 바꾸면 문서 공식이 되고,
`E = P1·E1 + P0·E0`, `δ = E1 − E0`로 정리하면

```
P1·E1 − P0·E0 = (P1 − P0)·E[IC] + 2·P1·P0·δ
```

이라 "점유율이 불균형이면 δ = 0이어도 0이 아니다"라는 결론은 그대로 맞다. **결정 1은 유지된다.** 다만 §1.1에
"어느 코딩이든 interaction의 평균 IC는 δ가 아니다"로 고쳐 적어야 한다.

### 3.3 빠진 경우

- **연속 국면 가중 — 근거 부족.** rank IC는 `|s_t|`를 완전히 버린다. 연속 `z_t·x`를 family로 등록해도
  `sign(z_t)·IC_t(x)`일 뿐이라 "국면 강도에 비례하는 가중"은 이 틀에서 표현 자체가 불가능하다. 이 점은 결정 1을
  **더 강하게** 뒷받침하므로 문서에 한 줄 적는 것이 좋다. 크기 가중 검정을 원하면 Phase C에서 `IC_t = α + δ·z_t + ε`
  (연속 회귀)를 진단으로 추가하는 길이 있으나, 이번 계약은 이진 `s_t`로 고정했으니 다음 사전등록 후보다.
- **동점 — 맞다.** 위 §3.1. `z_t = 0`이면 `cut: gt_zero`가 `s=0`으로 보내므로 δ 검정에는 문제가 없다.
- **시장 가중 — 맞다.** `daily_market_weighted_ic`(`metrics.py:154`)는 `Σ n_m·IC_m / Σ n_m`이고 `s_t`가 두 시장에
  공통이라 `sign(s_t)`가 밖으로 나온다. 시장별 `min_names` 탈락도 `s`와 무관하다. `03` §6.3 시장별 분해가 있으니 충분하다.
- 적혀 있지 않지만 중요한 비동치 하나: interaction family를 Phase A/B로 스캔하면 **temporal placebo가 `s·x`를
  통째로 밀어** 국면 지속성 때문에 약해진다(`11` §8.4). 조건부 δ + 국면 circular-shift(G4)는 그 문제를 정면으로 다루는
  더 좋은 검정이다. 결정 1의 근거로 추가할 가치가 있다.

## 4. `01_stage0_daily_ic_persistence.md` — 단계 0

### 4.1 기존 통계를 바꾸지 않는다 — 맞다

`scan_cell`(`horizon_scan_runner.py:497~663`)은 `market_ic → daily → values/sessions → 통계 → (spread)` 순서로 계산하고

계산 경로를 건드리지 않는다. 기본값 `None`이면 분기 자체가 없다.

### 4.2 정합성 검사 항목 — 맞다, 하나 추가 권고

§4.1 표의 재계산 규칙은 `scan_cell`과 일치한다. `ic_std`는 `ddof=1`, `kospi_weight_mean`은 `market_weight_means`가
`pivot … fill_null(0)`로 한쪽 시장만 있는 날을 가중 1/0으로 넣는 것과 `n_kospi / n_obs`(NULL→0) 재계산이 같다.
`n_hac_pairs_min`(`n_hac_pairs(sessions, lag)`)도 저장된 `formation_session_idx`로 재계산할 수 있으니 검사 표에 넣기를 권한다.

### 4.3 `q5_spread` 컬럼 배치 — 근거 부족 (경계 사례)

`daily_spread`는 `min_names_for_spread=50` 기준, `daily` IC는 `min_names=20` 기준으로 날짜 집합이 다르다. 보통은 spread
날짜 ⊆ IC 날짜지만, 한 시장이 50종목 이상인데 피쳐가 전부 동점이라 IC가 NaN으로 빠지는 날은 spread만 남는다. `trade_date`
left join으로 `q5_spread`를 IC 행에 붙이면 그 날의 spread가 사라져 `mean(q5_spread) ≠ q5_spread_raw`가 되고 reconcile이
실패한다. 드물지만 "reconcile 실패 = run 실패"로 정했으므로 `daily_spread`를 별도 작은 parquet로 두거나 full outer join으로
적는 것이 안전하다.

## 5. `02_stage1a_exposure_beta_families.md` — 단계 1a

### 5.1 잔차 베타 primary / 원수익률 베타 secondary — 맞다 (근거 문장 하나 부정확)

- 라벨: `labels.py:132`/`:367` `bench_ret = AVG(fwd_ret) OVER (trade_date, market)` — 동일가중, 시장별. `price.py:66`
  `market_ret = AVG(log_ret) OVER (PARTITION BY trade_date, market)` — 같은 개념(모집단은 valid session vs
  `all_quality_valid_sessions`로 조금 다름). 정합적이다.
- `Cov(r_i, f) = β_{i,m}·Cov(r_m, f) + Cov(e_i, f)`이므로 "원수익률 베타 = 시장 베타 × 시장–요인 베타 + 잔차 베타"는
  맞다. primary를 잔차 기준으로 두는 이유로 충분하다.
- 부정확한 문장: "시장 요인과 같이 움직이는 부분은 이미 라벨에서 빠져 있다". 라벨은 시장 **평균**을 뺀 것이라
  `β_i = 1`인 종목에서만 시장 요인이 사라진다. 시장 베타가 1이 아닌 부분 `(β_i − 1)·r_m`은 라벨에 남고, 그래서
  `px_market_beta`가 IC를 가질 수 있다(BAB). 결정은 그대로 두고 문장만 "라벨은 시장 평균 중립이고 베타 중립은 아니다"로
  고치는 것이 맞다.

### 6.1 통계량이 국면 지속성을 막나 — HAC 단독으로는 아니다, G4와 함께 맞다

`newey_west_tstat`(`metrics.py:267`)는 `formation_session_idx` 거리 ≤ lag인 쌍만 자기공분산에 넣는 Bartlett 커널이다.

| `market_up` | 0.565 | 86 | ≈ 29 |
| `liq_high` | 0.424 | 40 | ≈ **63** |
| `term_steep` | 0.466 | — | — |
| `krw_weak_20d` | 0.55 | — | — |

2023-01-24(설), 2023-05-05, 2023-10-03 같은 KRX 휴장 평일이 행으로 있고 값은 전 세션 복사다. 결과:

- `03` §2의 "인덱스 `t−k`는 KRX 세션 기준(fact의 feature_date가 KRX 세션)"은 2014~2023년에 틀리다.

  갑자기 12개월이 된다. `median_252` 안에 약 6%의 복사값이 들어간다.
- `IC_t`(KRX 세션)와 `trade_date`로 inner join하면 비세션 행은 빠지므로 **look-ahead는 아니다**. 창 길이의 뜻이
  시기마다 달라지는 정의 문제다.
- 단계 1a 마트는 fact를 종목 panel(KRX 세션)에 join한 뒤 LAG를 ticker별 valid session으로 잡으므로 영향이 없다.

해법은 §1 M3. 국면 시계열을 KRX 세션 격자에서 계산한다고 계약에 적는 쪽이 fact 재빌드보다 안전하다(fact를 다시 만들면
`00_survey/00` §4의 상관표와 `feat_common` 소비자도 같이 움직인다).

### 6.6 그 밖에
