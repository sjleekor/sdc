## 3. ★ 호출량이 162,000 → 83,700으로 준다

응답 구조 두 가지를 확인했다.

### ① `hyslrChgSttus`가 과거 변동을 누적으로 준다

```
bsns_year=2023 요청  →  rows=14,  change_on 2019-03-22 ~ 2023-08-04
bsns_year=2018 요청  →  rows=1,   change_on '-' (그 시점 변동 없음)
```

**한 번 요청에 5년치 변동 이력이 온다.** 12년을 덮는 데 연도별 12회가 아니라 **3회**면 된다.

### ② 감사의견이 3개년씩 온다

```
bsns_year=2023 → 제76기(당기) · 제75기(전기) · 제74기(전전기)
bsns_year=2018 → 제71기(당기) · 제70기(전기) · 제69기(전전기)
```

12년을 덮는 데 **4회**면 된다.

### ③ `exctvSttus`를 1차 백필에서 뺀다

후보 피쳐가 "경영진 교체율" 하나뿐이고 근거도 얇은데, 12년 × 2,700 = **32,400 호출**이다.
같은 T3(전이) 축은 `hyslrChgSttus`(최대주주 변동)가 훨씬 강하게 덮고, 그쪽은 8,100 호출이다.
**필요해지면 나중에 받는다.**

### 재산정

| 엔드포인트 | 계획 | 확정 | 호출 |
|---|---|---|---:|
| `empSttus` | 12년 × 2,700 | 연도별 필수 | 32,400 |
| `hyslrSttus` | 12년 × 2,700 | 연도별 필수(수준 변수) | 32,400 |
| `hyslrChgSttus` | 12년 × 2,700 | **누적 → 3회** | **8,100** |
| 감사의견 | 12년 × 2,700 | **3개년씩 → 4회** | **10,800** |
| `exctvSttus` | 12년 × 2,700 | **1차에서 제외** | **0** |
| **합계** | **162,000** | | **83,700** |

**48% 감소. 키 3개 기준 3일 → 1.5일.**

계획의 "분기까지 올린다" 예외(`07` §2, +97,200)도 **불필요하다** —
`change_on`이 있어 연 1회 수집으로도 변동 시점이 정확하다.

## 4. 행 순서는 안정적이다 — `row_ordinal`로 간다

같은 요청을 두 번 보냈다.

```
1회차: [('남','반도체','21,210'), ('여','반도체','10,855')]
2회차: [('남','반도체','21,210'), ('여','반도체','10,855')]
순서 동일: True
```

**`row_ordinal`을 쓴다.** payload 해시 대안은 불필요하다.

**단 행 수는 연도마다 바뀐다** — 삼성전자 10→6, LG화학 10→8. 구분 차원(성별 × 사업부문)이
연도별로 달라지기 때문이다. `row_ordinal`은 **한 `(corp, year, reprt)` 응답 안에서만**
의미가 있고, UNIQUE 제약이 이미 그렇게 정의돼 있다(`07` §3). 문제없다.

## 5. ★ 대상 집합에 더 큰 문제가 있다

`07` §2는 대상을 "역사적 상장사"로 잡으라고 했고, `dart_filing_receipt_raw`를 그 근거로 썼다.
**그 전제가 틀렸다.**

`dart_filing_receipt_raw`는 `active_only=True`로 수집돼 **현재 상장사의 이력**만 담고 있다.
`dart_corp_master`의 ticker 매핑 법인 3,959개 중 **1,330개가 상폐 법인인데, 그중 receipt에
수집된 건 28개(2.1%)뿐**이다.

이건 N6만의 문제가 아니라 **DART raw 전체와 `daily_ohlcv`에 걸친 문제**라
[`survivorship_gap.md`](survivorship_gap.md)로 분리했다.

> **N6 착수 전에 S-1(대상 집합 확장)이 선행돼야 한다.**
> 16만 호출을 편향된 대상으로 돌리면 감사의견·부실 신호가 의미를 잃는다.
> 원래 계획은 N3를 선행 조건으로 뒀는데, **실제 선행 조건은 S-1이다** —
> corp_code 매핑은 이미 `dart_corp_master`에 다 있다.

## 6. 결정 (결과 보기 전에 고정)

`07` §6의 네 가지에 하나를 더한다.

1. **직원 수 정의** — `sm`(합계)을 쓴다. 정규직(`rgllbr_co`)과 계약직(`cnttk_co`)의
   구분 방식이 기업마다 다르고, 합계가 가장 안정적이다
2. **`hc_revenue_per_employee` 분모 시점** — 직원 수는 기말 기준, 매출은 기간 누적이므로
   **기말 기준으로 통일**한다
3. **감사의견 인코딩** — **이진**(적정 / 비적정). 비적정이 드물어 4단계는 표본이 안 나온다
4. **부호** — 감사 비적정 `−` 고정. 최대주주 지분·직원 증가는 **미고정임을 사전에 적는다**
5. **(신규) 합병·분할 보정** — 직원 수 점프가 경제적 변화인지 구조 변경인지 갈라낸다.
   LG화학 −37.7%가 그 사례다. ~~**`listed_shares` 급변([N1](../02_w1_daily_market_cap.md))
   또는 `dart_capital_change_raw`와 대조**해~~ 구조 변경 연도를 결측 처리한다

> **2026-08-18 정정 — 5번의 대조 원천이 틀렸다.** `dart_capital_change_raw`로는
> **동기가 된 LG화학 사례 자체를 못 잡는다.** 물적분할은 모회사 주식 수를 안 바꾸기
> 때문이다. lake(2026-08-12)로 확인 — LG화학 2019~2021 `dart_capital_change_raw`에
> 분할 흔적이 없고, `isu_dcrs_stle` 값 15종에 **합병·회사분할이 아예 없다**
> (`주식분할` 7,067건은 액면분할). `dart_filing_receipt_raw`의
> **`합병등종료보고서(분할)`**은 2020-12-04로 정확히 찍혀 있다.
> 확정 규칙(2게이트 + 플래그 + 임계값 30%)은 [`../07` §6](../07_w3_periodic_report_extras.md#6-결과-보기-전에-고정할-것--2026-08-18-확정-n6-7).
