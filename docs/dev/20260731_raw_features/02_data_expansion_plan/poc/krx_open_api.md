# 조사 — KRX Open API로 스크래핑 경로를 대체할 수 있는가

- 조사일: 2026-08-16
- 계기: 2026-08-16 sj2-server IP가 KRX Data Marketplace에서 차단됐다.
  안내문이 **원인을 명시**했다 — 페이싱 문제가 아니라 **이용약관 위반**이다.
- 상태: **인증키 신청 완료, 승인 대기.** 아래 §4의 응답 필드는 아직 미확정이다.

---

## 0. 한 줄 결론

**핵심은 되고, 일부는 안 된다.**

N1(일별 시총)·N3(PIT 유니버스)·지수 시세는 Open API로 **그대로 옮길 수 있다.**
`flows`(투자자별 거래실적·공매도)·N7(PER/PBR/배당수익률)·N4(지수 구성종목)는
**Open API 서비스 목록에 없다.** 별도 경로가 필요하다.

---

## 1. 왜 이 조사를 하게 됐나

2026-08-16, sj2-server IP가 KRX에서 차단됐다. 안내 페이지 전문:

> **KDM 이용 제한 안내**
> 자동화 수단을 통한 비정상 대량 조회가 감지되어 해당 IP의 접속이 일시적으로 제한되었습니다.
> KRX Data Marketplace 이용약관 **제10조 제2호**는 자동화 수단을 이용한 정보 무단 수집·복제·배포를
> 금지하고 있으며, **제6조 제2항**에 따라 약관 위반시 홈페이지 이용이 제한될 수 있습니다.
> 해당 IP는 탐지일로부터 **1일간** 접속이 제한되며 (…)
> KRX Data Marketplace의 화면 다운로드 기능 이용, 데이터 상품 구입 또는
> **KRX Open API(openapi.krx.co.kr)** 등 공식 경로를 이용해 주시기 바랍니다.

**이 문장이 지금까지의 대응 방향을 무효로 만든다.**

O-14에서 우리는 이걸 페이싱 문제로 읽고 스로틀을 통일했다(0.4s → 1.5~4.0s).
그 뒤 09:07~09:11에 **0.32 req/s**, 즉 어젯밤보다 3배 느린 페이스로 돌렸는데도
**95요청 만에 다시 차단됐다.** 1차 차단은 9시간 만에 풀렸는데 재차단은 5분 만에 왔다.

약관 제10조 제2호는 **자동화 수단에 의한 수집 자체**를 금지한다.
속도 조건이 붙어 있지 않다. **느리게 하면 허용되는 종류의 규칙이 아니다.**

그래서 스로틀링 작업은 여기서 멈춘다. 남은 질문은 하나다 —
**공식 경로가 우리 수요를 덮는가.**

## 2. 서비스 사양 (확인됨)

| 항목 | 값 |
|---|---|
| 포털 | `https://openapi.krx.co.kr` |
| API 베이스 | `https://data-dbg.krx.co.kr/svc/apis/{그룹}/{엔드포인트}` |
| 인증 | HTTP 헤더 `AUTH_KEY: <키>` + `Content-Type: application/json` |
| 요청 파라미터 | `basDd` (YYYYMMDD) — **호출당 하루** |
| 응답 | JSON, 배열 키 **`OutBlock_1`** |
| 호출 한도 | **하루 10,000회** |
| 비용 | 무료 |
| 키 유효기간 | 1년 (갱신) |

**응답 모양이 지금 MDC 경로와 같다.** MDC도 하루 단위 전종목 JSON을 준다.
어댑터 교체 비용이 낮다는 뜻이다.

### 2.1 함정 — 키만으로는 못 쓴다

**엔드포인트마다 "API 이용 신청"을 따로 해야 한다.**
인증키가 승인돼도 서비스별 신청이 없으면 해당 엔드포인트는 응답하지 않는다.
구현 전에 신청 상태부터 확인해야 한다.

### 2.2 확인된 엔드포인트

| 그룹 | 경로 | 내용 |
|---|---|---|
| `sto` | `stk_bydd_trd` | 유가증권 일별매매정보 |
| `sto` | `ksq_bydd_trd` | 코스닥 일별매매정보 |
| `sto` | `stk_isu_base_info` | 유가증권 종목기본정보 |
| `sto` | `ksq_isu_base_info` | 코스닥 종목기본정보 |
| `idx` | `kospi_dd_trd` | KOSPI 시리즈 일별시세정보 |

---

### 2.3 "공식이니까 허용된다"고 보면 안 된다 — 게이트 (2026-08-16 추가)

**이 조사가 놓친 지점이다.** KIS는 약관 확인을 별도 작업(K-6c)으로 뒀으면서
KRX Open API는 "공식 경로"라는 이유로 그냥 통과시켰다.

[공식 이용약관](https://openapi.krx.co.kr/contents/OPP/INFO/OPPINFO002.jsp)에는
**비상업 목적 제한 · 제3자 제공 제한 · 출처 표시 · 계약 종료 후 수신 정보 이용 제한**이 있다.

**엔드포인트가 공식이라는 사실이 장기 보관과 파생물 이용 권한까지 주지는 않는다.**
지금 겪는 문제가 정확히 **기술적 접근 가능성과 사용 권한을 혼동한 결과**다.
같은 실수를 반복하지 않으려면 K-0과 같은 수준의 게이트가 필요하다.

- [ ] 우리 용도(연구·백테스트)가 **비상업 목적**에 해당하는가
- [ ] PostgreSQL·parquet **장기 보관**이 허용되는가
- [ ] 파생물(피쳐·마트)의 지위는 무엇인가
- [ ] **계약 종료 시** 이미 받은 데이터를 어떻게 해야 하는가

같은 질문을 **공공데이터포털**(§4.1b)과 **KIS**(K-6c)에도 적용한다.

## 3. 서비스 목록 대조 — 있는 것과 없는 것

출처: [서비스 목록](https://openapi.krx.co.kr/contents/OPP/INFO/service/OPPINFO004.cmd)

### 3.1 제공된다

  신주인수권증권·증서 일별매매정보

## 4. 우리 파이프라인과 맞추면

경로별 현황은 [`krx_access_inventory.md`](krx_access_inventory.md)에 따로 있다.

| 우리 수요 | 현재 경로 | Open API | 판정 |
|---|---|---|---|
| **N1** 시총·거래대금·상장주식수 | pykrx → KRX | 일별매매정보 | **필드 확인 필요** |
| **N3** PIT 유니버스 | pykrx → KRX | 같은 호출 | ✅ 별도 호출 불필요 |
| `daily_ohlcv` | naver 수정주가 | 같은 호출 | ✅ 단 **미수정 주가** |
| `stock_master` (일 유니버스) | **FDR → KRX MDC** | 종목기본정보 | **필드 확인 필요** |
| common 지수 시세 | MDC | 시리즈 일별시세정보 | ✅ |
| common 등락종목수·거래대금 | MDC (`MDCSTAT01501`) | ? | 확인 필요 |
| **`flows` 투자자 순매수** | MDC | **없음** | ❌ |
| **`flows` 공매도** | MDC | **없음** | ❌ |
| **N7** BPS/PER/PBR/EPS/DIV/DPS | pykrx → KRX | **없음** | ❌ |
| **N4** 지수 구성종목 | pykrx → KRX | **없음** | ❌ |

### 4.1 응답 필드 — **확인됨** (2026-08-16 갱신)

> **초판은 이 항목을 "키 승인 후에나 알 수 있는 미확정"으로 뒀다. 그럴 필요가 없었다.**
> 외부 리뷰에서 **주식 서비스 상세 페이지의 embedded schema를 디코드**해
> 세 필드를 확인했다.

| 필드 | 뜻 |
|---|---|
| `MKTCAP` | 시가총액 |
| `LIST_SHRS` | 상장주식수 |
| `ACC_TRDVAL` | 거래대금 |

**N1이 받으려는 것 그대로다. 공식 스키마이지 정황이 아니다.**
그 외 확인된 필드: `BAS_DD`·`ISU_CD`·`ISU_NM`·`TDD_CLSPRC`.

**K-2는 더 이상 키 발급 blocker가 아니다.** 남은 live 검증 대상은
**값 품질과 과거일자 coverage**뿐이다.

> **철회.** 초판이 든 간접 근거 — "FDR이 매일 치는 `MDCSTAT01501`의 응답 키가
> `OutBlock_1`이다" — 는 **경로 분석 자체가 틀려서 성립하지 않는다.**
> FDR은 `MDCSTAT01501`을 치지 않는다
> ([`krx_access_inventory.md`](krx_access_inventory.md) §2.1·§7).
> 위 표는 그 근거와 무관하게 공식 스키마에서 나왔다.

### 4.1b 그리고 이 질문을 우회하는 문이 하나 더 있다

[`n7_n4_alternatives.md`](n7_n4_alternatives.md) §3에서 나왔다.
**공공데이터포털 `금융위원회_주식시세정보`(`getStockPriceInfo`)가
`mrktTotAmt`(시가총액) · `lstgStCnt`(상장주식수) · `trPrc`(거래대금)를 준다.**

| | |
|---|---|
| 엔드포인트 | `apis.data.go.kr/1160100/service/GetStockSecuritiesInfoService/getStockPriceInfo` |
| 범위 조회 | **`beginBasDt` / `endBasDt` 지원** — Open API의 하루 단위보다 낫다 |
| 한도 | 개발계정 하루 10,000회 (운영계정 증설 신청 가능) |

**KRX 키 승인을 기다리는 동안 이쪽으로 갈 수도 있다.**
같은 KRX 통계를 다른 공식 포털이 재공개하는 것이다.

> **2026-08-16 갱신 — 필드와 범위 파라미터는 공식 명세에서 확인됐다.**
> 다만 **"범위 조회 = 한 번에 백필"로 읽으면 안 된다.**
>
> - **`endBasDt`는 "미만" 조건이다.** inclusive로 구현하면 **하루가 어긋난다**
> - 응답은 `pageNo`·`numOfRows`·`totalCount` **pagination**이다.
>   최대 page size를 확인하지 않아 실제 요청 수를 모른다
> - **과거 보유기간(이력 깊이)도 미확정이다**
>
> 필드·범위 지원은 **확인**, 이력 깊이·최대 page size·pagination 요청 수는 **미확정**이다.

**확정 방법**: 키 승인 후 상세 페이지의 TEST 버튼 또는 개발명세서 다운로드. 한 번에 끝난다.

### 4.2 호출량 — 스크래핑보다 유리하다

일별매매정보 한 호출이 **그날 그 시장의 전종목**을 준다. 즉:

- N1(시총 백필)과 N3(PIT 유니버스)가 **같은 호출로 합쳐진다**
- 2014-06 ~ 현재, 2개 시장 → 약 **6,000 호출**
- **하루 10,000회 한도 안에 들어간다** — 하루면 전량 백필이 끝난다

지금 스크래핑 경로는 N1 6,000 + N3 290을 따로 부르고, 그마저 차단으로 못 돈다.

**유가증권 일별매매정보는 2010-01-04부터 제공된다.**
우리 표본 시작(2014-06)보다 앞선다 — 범위 손실이 없다.

## 5. 부수 효과 — 결정 4의 vintage 결함이 같이 풀린다

Open API는 **KRX 원주가(미수정)** 를 준다.
현재 `daily_ohlcv`는 naver 수정주가고, **naver가 분할·병합 때 과거를 소급 재작성하는 것이
결정 4 vintage 결함의 원인**이다([`n1_adjusted_price_vintage.md`](n1_adjusted_price_vintage.md)).

원주가 + 같은 응답의 `상장주식수` 차분이면 **조정 계수를 우리가 PIT로 계산할 수 있다.**
상류가 언제 재작성하든 무관해진다.

| | 현재 | 원주가 기반 |
|---|---|---|
| 조정 주체 | naver | 우리 |
| 소급 재작성 | 상류가 임의로 | 없음 (원주가는 불변) |
| V-1b 전량 재수집 | 필요 | **불필요** |
| V-3 트리거 | `listed_shares` 차분 → 재수집 | 차분 → **조정 계수 재계산** |
| 액면병합(003060 케이스) | naver가 조정 안 함 → 잔존 | 우리가 처리 |

**지금 결정할 사안은 아니다.** 다만 공식 경로 전환이 **덤으로 가져오는 이득**이라 기록한다.
V 묶음 실행 순서를 정할 때 이걸 먼저 본다.

## 6. 빈 항목을 어떻게 덮을 것인가

`flows` · N7 · N4는 Open API에 없다. KRX 안내문이 제시한 나머지 공식 경로는 둘이다.

| 경로 | 적합 | 부적합 |
|---|---|---|
| **화면 다운로드** | 일회성 과거 백필 | 일별 갱신 — 수동이라 자동화 불가 |
| **데이터 상품 구입** | 일별 갱신 | **조건 미확인** — 판매 페이지가 500 에러 |

### 6.1 `flows` — 조사 완료 (2026-08-16)

→ [`flows_alternatives.md`](flows_alternatives.md)

**7 metric 중 5개는 KIS Developers로 대체 가능하고, 2개는 갈 곳이 없다.**
갈 곳 없는 둘은 **외국인 보유주식수**와 **공매도 잔고 수량**이다.

**공공데이터포털은 답이 아니었다** — 금융위 라인업이 KRX Open API와 같고,
"공매도"로 나오는 건 민간 벤더의 파생 스코어다.

그리고 **급하지 않다는 게 밝혀졌다.** `flows`는 하루 38요청이고
차단은 백필 6,000요청에서 났다. 이미 2007년부터의 이력을 갖고 있어
필요한 것도 백필이 아니라 forward-fill이다.

### 6.2 N7 · N4 — 조사 완료 (2026-08-16)

→ [`n7_n4_alternatives.md`](n7_n4_alternatives.md)

**둘 다 폐기가 아니라 축소다.** 기존 데이터가 0이라 열리지 않을 줄 알았는데,
조사해보니 두 패키지의 **목적이 KRX 없이도 상당 부분 달성된다.**

- **N7** — 진단 근거 셋(I1·I7·I6)이 **전부 다른 작업으로 이미 귀속돼 있었다.**
  남는 매핑 검증은 횡단면 문제라 KIS로 된다
- **N4** — 목적 B는 N2로 이미 돌아가고, 목적 A는 **업종분류 현황 CSV가 더 맞는다**
