## 2. ★ 자릿수가 섞인다 — 계획의 전제가 또 틀렸다

무작위 150종목 표본이다.

| 자릿수 | 건수 |
|---|---:|
| 2 | 3 |
| **3** | **52** |
| 4 | 21 |
| **5** | **74** |

**결측 0 · 오류 0.**

계획 §5는 "`induty_code`는 3자리(KSIC 소분류)"를 전제했다. 실제로는 **2·3·4·5자리가 섞인다.**
5자리가 가장 많다(세세분류).

> **따라서 "N자리로 자른다"는 규칙이 원본 길이에 의존하면 안 된다.**
> **2자리 prefix는 길이에 무관하게 항상 KSIC 중분류를 준다.**
> `264→26` · `5821→58` · `21100→21` · `65121→65`. 2자리 코드는 그 자체가 중분류다.

검증해보면 의미도 맞는다.

| 코드 | 2자리 | KSIC 중분류 | 법인 |
|---|---|---|---|
| 264 | **26** | 전자부품·컴퓨터·영상·음향·통신장비 | 삼성전자 |
| 5821 | **58** | 출판업 | 크래프톤 |
| 21100 | **21** | 의료용 물질 및 의약품 | 셀트리온 |
| 50112 | **50** | 수상 운송업 | HMM |
| 65121 | **65** | 보험 및 연금업 | 삼성화재 |

### 2자리 prefix 그룹 분포 (150종목 기준)

| 항목 | 값 |
|---|---|
| 그룹 수 | **36** |
| 최대 그룹 | `26` 21건 (14%) |
| 상위 | 26(21) · 58(14) · 24(9) · 64(9) · 29(9) · 20(8) · 21(8) · 46(8) |
| **종목 1개뿐인 그룹** | **15** |

150종목에서 36그룹이면 3,959 전체에서는 KSIC 중분류 77개 중 상장사가 있는 것 대부분이
나올 것으로 본다. **소수 업종 병합이 필요하다는 것도 확인됐다** — 표본에서 이미 15개 그룹이
1종목이다.

## 3. ★ 금융과 지주회사가 갈리지 않는다

**LG(비금융 지주)와 KB금융(은행지주)이 똑같이 `64992`다.** 5자리 원본에서도 같다.

계획 §5의 권고안 B는 "2자리 prefix + **금융·지주 override**"였는데,
**override의 근거가 될 코드 차이가 없다.** `corp_cls`도 둘 다 `Y`라 쓸 수 없다.

> **즉 `induty_code`만으로는 금융업을 갈라낼 수 없다.** 이건 매핑 설계로 풀 문제가 아니라
> 원천의 한계다.

근본적으로 옳은 판정 기준은 **재무제표 계정 구조**다. 금융업은 매출·매출원가 구조가 다르고,
그게 애초에 `fin_gross_profitability`가 금융업에서 개념 미성립인 이유다.
**다만 그건 `metric_rules` 영역이고 N2 범위가 아니다.**

이 사실이 §5 결정을 바꾼다.

## 4. ★ `acc_mt != '12'`가 4%다 — 조사로 끝나지 않는다

| `acc_mt` | 건수 (150 표본) |
|---|---:|
| **12** | 144 |
| **03** | **4** |
| **06** | **1** |
| **11** | **1** |

**비12월 결산이 6/150 = 4.0%.** ticker 매핑 법인 3,959로 환산하면 **약 158개 법인**이다.

`03_w1_company_profile.md` §2에서 지적한 대로 마트가 결산월을 12월로 하드코딩하고 있다.

```sql
-- research/etl/marts/metric_vintages.py — _calendar_period_end_expr
WHEN '11013' THEN make_date(year, 3, 31)   -- 1분기
WHEN '11011' THEN make_date(year, 12, 31)  -- 사업보고서
```

3월 결산 법인의 1분기 보고서는 실제 `period_end`가 6/30인데 3/31로 잡힌다.
분기 standalone 계산(`Q2 = half − Q1`), YoY 비교, TTM이 전부 어긋난다.

> **V4 판정: 수정이 필요하다.** 4%는 무시할 수준이 아니다.
> `metric_vintages.py`의 period_end 산출을 `acc_mt` 기반으로 고치는 별도 작업이 뒤따른다.

정확한 법인 수와 시총 비중은 전량 수집(N2-7) 후 확정한다.
