# 조사 — N7 · N4 대체 경로 (K-6d)

- 조사일: 2026-08-16
- 계기: KRX Open API에 **PER/PBR/배당수익률과 지수 구성종목이 없다**
  ([`krx_open_api.md`](krx_open_api.md) §3.2). 두 패키지는 **기존 데이터가 0이라**
  대체 경로가 없으면 열리지 않는다.
- 선행: [`flows_alternatives.md`](flows_alternatives.md) — 같은 축의 `flows` 조사

## 0. 한 줄 결론

**둘 다 폐기가 아니라 축소다. 그리고 N7은 대체재보다 근거가 먼저 문제였다.**

N7이 팔던 진단 근거 셋(I1·I7·I6)을 원문에서 확인해보니 **전부 다른 작업으로 이미 귀속돼 있다.**
남는 가치는 있지만 **6,000일 이력이 필요 없다.**

N4는 목적 둘 중 하나가 이미 충족됐고, 남은 하나는 **지수 구성종목보다 나은 원천이 있다.**

## 1. N7 — 근거부터 무너진다

### 1.1 대체재 목록

| 후보 | PER/PBR | 비고 |
|---|---|---|
| KRX Open API | ❌ | 확정 |
| 공공데이터포털 `주식시세정보` | ❌ | 다만 §3의 별건이 나왔다 |
| 공공데이터포털 `기업재무정보` | ❌ | 재무제표 항목이지 비율이 아니다 |
| **KIS `inquire_price`** (`FHKST01010100`) | **✅** `per`·`pbr`·`eps`·`bps` | 독립·무료. **현재값만** |
| KRX 데이터 상품 / Koscom datamall | ? | **두 페이지 다 500 에러** |
| KRX 화면 다운로드 | ✅ | `MDC0201020502` PER/PBR/배당수익률(개별종목) |

> KIS 필드는 서드파티 문서 다수가 일치하는 것으로 확인했다. **공식 명세 대조는 안 했다.**

### 1.2 그런데 근거 셋이 이미 다른 데로 귀속돼 있다

[`08_w3_valuation_and_macro.md`](../08_w3_valuation_and_macro.md) A1은 N7의 목적을
**`fin_value_z` 교차검증 + I1·I7 진단**으로 적었다.
[`10_known_issues.md`](../../01_feature_candidate/10_known_issues.md)를 다시 읽으면
셋 다 원인이 이미 확정돼 있다.

**I1은 데이터 문제가 아니라 SQL 버그다. 그리고 이미 끝났다.**

```sql
LEAST(GREATEST(fin_book_to_market, p01), p99)   -- DuckDB는 NULL을 건너뛴다
LEAST(GREATEST(NULL, 0.1), 0.9)  →  0.1        -- NULL이 아니다
```

**정정 (2026-08-16 확인).** 이 조사를 쓸 때 "고치면 된다"고 적었는데,
확인해보니 **수정·재실행·결과 갱신까지 전부 끝나 있다.**
`fin_scan.py`에 `CASE WHEN <ratio> IS NULL THEN NULL` 가드가 들어가 있고,
결정성 게이트를 통과해 Phase B 재실행까지 마쳤다(`0e98c66`, `4a89b7c`).

| family | 이전 IC | 수정 후 IC |
|---|---:|---:|
| `fin_value_z` (bucket 40–60) | +0.0348 | **+0.0692** |
| `fin_value_z` (cum 0–120) | +0.0722 | **+0.1384** |

**규칙을 어긴 29.2%가 빠지면서 신호가 선명해졌다.** coverage 0.6073 → 0.4299.

**독립 PER/PBR이 여기 기여할 게 없었다는 결론은 그대로다.** 코드로 끝났다.

**I7은 밸류에이션 원천 문제가 아니라 DART canonical 매핑 문제다.**
`revenue` 8,103행 / `gross_profit` 7,362행 vs `net_income` 141,011행.
§5.5.3이 **"XBRL fallback 보강이 정답"**이라고 이미 결론냈다.

**~~등급 B 상한(I6)은 정정분 재수집이 답이다.~~ — 거꾸로 인용했다 (2026-08-16 정정).**

`10_known_issues.md` §5.5.2의 제목이 **"I6 — 재수집으로 해결되지 않는다 (계획 변경)"**이다.
정정 비율을 metric별로 분해했더니 전부 0.10 언저리였다.

| metric | 정정 비율 |
|---|---:|
| `net_income` | 0.1056 |
| `operating_cash_flow` | 0.1013 |
| `total_equity` · `total_assets` | 0.1012 |
| `gross_profit` | 0.1002 |
| `revenue` | 0.0990 |

**약 10%는 이 원천의 기본 정정률이다.** 특정 metric이 더러운 게 아니다.
그래서 §3단계에서 **"정정분 재수집(I6)은 빠지고"**라고 명시했다.

**I6은 해결 작업이 아니라 등급 임계값·방법론 결정 사항이다.**
→ **N7의 선행조건에서 뺀다. 남은 선행은 I7 하나다.**

### 1.3 그래서 N7에 남는 것 — 그리고 그 범위는 좁다

**I7을 고친 뒤 canonical 매핑이 맞는지 독립 원천으로 대조하는 것.**
윈저라이즈 버그를 고쳐도 매핑이 틀렸는지는 여전히 모른다.

**다만 6,000일 이력이 필요 없다.** 매핑 검증은 횡단면 문제다.

> **초판은 여기서 "매핑 검증이 된다"고 뭉뚱그렸다. 절반도 안 된다 (2026-08-16 정정).**
>
> `fin_value_z`는 **B/M · E/P · CFO/P · S/P** 네 성분이다(`fin_scan.py`).
> KIS `inquire_price`가 주는 건 `per`·`pbr`·`eps`·`bps`다.
>
> | 성분 | KIS로 검증 |
> |---|---|
> | B/M | ✅ `pbr`·`bps` |
> | E/P | ✅ `per`·`eps` |
> | **CFO/P** | ❌ 영업현금흐름 없음 |
> | **S/P** | ❌ 매출 없음 |
>
> **그리고 I7이 바로 `revenue`·`gross_profit` 문제다** — KIS로는 **I7 수정 결과를 검증할 수 없다.**
> N7 축소안이 "I7을 고친 뒤 검증한다"고 적었는데, 정작 그 부분을 못 본다.

**검증 범위를 B/M·E/P로 명시한다.** CFO/P·S/P와 I7 수정 결과는
**다른 원천을 따로 찾거나, 검증하지 않는 것으로 남긴다.**

### 1.4 N7 권고 — 축소

- **취소**: 새 테이블 `daily_market_fundamental` + 6,000 호출 백필
- **대체**: KIS 횡단면 대조 (시점 수 개)
- **선행**: **I7 수정 하나다.** **I1은 이미 끝났고**(§1.2),
  **I6은 재수집으로 해결되지 않아 선행조건에서 뺐다**(§1.2 정정)
- **검증 범위 명시**: **B/M · E/P만.** CFO/P · S/P와 **I7 수정 결과는 KIS로 못 본다**(§1.3)
- **미결**: 기존 acceptance criteria **C4(DIV vs payout yield)** 와
  **C5(KRX-PBR 기반 value z의 IC 비교)** 를 어떻게 할 것인가 (§1.5)
- **미확정**: KIS에 `DIV`(배당수익률)가 있는가 — `per/pbr/eps/bps`만 확인됐다

### 1.5 축소로 수행 불가능해진 완료 기준 — 상태를 정해야 한다 (2026-08-16 추가)

기존 N7-8의 acceptance criteria C1~C5는 `10_work_breakdown.md`에 그대로 남아 있다.
**그런데 축소안으로는 둘을 수행할 수 없다.**

| | 내용 | 축소안에서 |
|---|---|---|
| **C4** | KRX `DIV` vs 우리 `payout yield` | **수행 불가 확정** — 실호출로 80필드를 확인했고 `DIV`가 없다 |
| **C5** | KRX-PBR 기반 value z와 `fin_value_z`의 **IC 비교** | **현재값 횡단면만으로는 미래수익률 IC를 못 낸다** |

C4는 2026-08-16 실호출로 확정됐다
([`flows_alternatives.md`](flows_alternatives.md) §5b.3).

**호출을 줄인 게 아니라 완료 기준 일부를 수행 불가능하게 만든 것이다.**
문서상으로는 여전히 C1~C5를 다 할 수 있는 것처럼 보인다.

- [ ] C4·C5를 **폐기**하는가, **다른 공식 시계열로 이전**하는가 — 상태를 명시할 것

## 2. N4 — 목적 하나는 이미 충족, 남은 하나는 **미해결**

### 2.1 목적 B는 N4 없이 산다

[`05_w2_industry_index.md`](../05_w2_industry_index.md) §1의 목적 B는
관계 피쳐(산업 모멘텀·리드래그·업종 수급)의 **"같은 업종 종목 집합"** 재료다.

**이미 있다.** N2-7b 완료로 확인했다.

```
corps | with_induty | codes | profiled
 3959 |        3959 |   630 |     3959
```

`definitions/industry_groups.py`가 이 `induty_code`를 KSIC 중분류로 접어
`fin_scan.py`의 횡단면 z-score에 쓰고 있다. **지수 구성종목이 아니어도 된다.**

### 2.2 목적 A — 지수 구성종목보다 나은 원천

목적 A는 **"업종이 실제로 바뀐 기업이 몇 개인가"** = N2의 PIT 약점 크기다.

| 후보 | 결과 |
|---|---|
| KRX Open API | 구성종목 **없음** (확정) |
| 공공데이터포털 | **없음** |
| KIS `inquire_index_category_price` | 업종별 시세, **현재 시점** |
| **KRX `업종분류 현황`** (`MDC0201020506`) | **전종목 업종 CSV 다운로드** |

**화면 다운로드는 차단 안내가 명시적으로 허용한 공식 경로다.**

**잡음 하나는 준다.** 계획 문서 스스로 경고한 부분이다.

> 지수 편입·제외에는 업종 변경 말고도 **신규상장, 유동성 기준 미달, 지수 방법론 개편**이
> 전부 섞인다. 측정 3의 정의가 이 작업에서 가장 조심할 부분이다.

업종분류 현황에는 그 잡음이 없다 — 업종을 직접 읽는다.

> ### ⚠ 그런데 핵심 문제는 그대로다 (2026-08-16 정정)
>
> **초판은 "업종분류 현황이 더 맞다"로 결론냈다. 과했다.**
>
> 목적 A는 **DART `induty_code`, 즉 KSIC의 PIT 약점**을 재는 것이다.
> 그런데 **KRX 업종분류는 KSIC이 아니다.** `05` §5가 이미 표로 적어뒀다 —
> "분류 깊이: N2는 **표준산업분류**(조정 가능), N4는 **KRX 업종**(고정)".
>
> **지수 구성종목 안이 안고 있던 cross-taxonomy 문제를 그대로 물려받는다.**
> KSIC 변경과 KRX 업종 변경을 구분하지 못하고,
> **KRX 분류 기준 자체가 개정된 사건도 기업의 실제 업종 변경처럼 보인다.**
>
> **따라서 "과거 기준일 조회 가능 여부"만 남은 분기점이라고 본 것은 틀렸다.**
> 분기점이 둘이다.
>
> 1. 과거 기준일 조회를 받는가
> 2. **안정적인 KSIC ↔ KRX 업종 crosswalk를 만들 수 있는가**, 그리고
>    실제 변경 사건으로 검증되는가
>
> **2번이 없으면 목적 A를 달성했다고 보지 않는다.**
> 비교 가능한 KSIC 계열 필드가 없다면 **업종분류 현황은 목적 A의 대체안이 아니다.**

### 2.3 N4 권고 — 재정의

- **취소**: `krx_index_constituent` 테이블 + 3,600 호출 지수 구성종목 수집
- **대체 후보**: 업종분류 현황 월별 스냅샷 — **확정 아님**
- **확인 필요 (둘. 초판은 하나로 적었다)**
  1. 그 화면이 **과거 기준일 조회를 받는가**
  2. **KSIC ↔ KRX 업종 crosswalk가 가능한가** — 안 되면 대체안이 아니다
- **목적 B는 이 결정과 무관하다** — 이미 N2로 돌아간다
- **둘 다 안 되면**: 목적 A를 **측정하지 못한 채** N2의 PIT 약점을 한계로 명시하고 간다.
  그게 정직한 결말이지 억지 대체안보다 낫다

## 3. 별건 — 공공데이터포털이 K-2를 우회한다

`금융위원회_주식시세정보`(`getStockPriceInfo`)의 응답 필드다.

```
basDt, srtnCd, isinCd, itmsNm, mrktCtg, clpr, vs, fltRt,
mkp, hipr, lopr, trqu, trPrc, lstgStCnt, mrktTotAmt
```

**`mrktTotAmt`(시가총액) · `lstgStCnt`(상장주식수) · `trPrc`(거래대금) — N1의 payload 그대로다.**

| | |
|---|---|
| 엔드포인트 | `apis.data.go.kr/1160100/service/GetStockSecuritiesInfoService/getStockPriceInfo` |
| 범위 조회 | **`beginBasDt` / `endBasDt` 지원** |
| 한도 | 개발계정 하루 10,000회 (운영계정 증설 신청) |
| 갱신 | 일 1회, 영업일 기준 익일 13시 이후 |

**K-2에서 "개발명세서를 봐야 안다"고 남겨둔 질문에 다른 문으로 답이 나왔다.**
KRX 승인을 기다리는 동안 이쪽으로 갈 수도 있다.

> **단정하지 않는다.** 필드 목록의 출처가 서드파티 문서다.
> 공식 활용가이드 대조와 **이력 깊이 확인**이 남아 있다.

## 4. 두 패키지를 어떻게 둘 것인가

**폐기가 아니라 축소다.** 원래 계획의 KRX 스크래핑 의존분만 덜어내면 목적은 살아남는다.

| | 원래 | 축소 후 | 잃는 것 |
|---|---|---|---|
| **N7** | 새 테이블 + 6,000 호출 | KIS 횡단면 대조 | **시계열 밸류에이션 피쳐 가능성** — 원래도 "피쳐가 아니라 진단"이었다 |
| **N4** | `krx_index_constituent` + 3,600 호출 | 업종분류 현황 스냅샷 | **지수 소속 기반 관계 피쳐** — 목적 B는 N2로 대체됨 |
