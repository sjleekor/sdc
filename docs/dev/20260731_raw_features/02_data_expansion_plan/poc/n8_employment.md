## 2. ★ 원계열과 계절조정이 `ITEM_CODE2`로 갈린다

`08` §B1.5가 "원계열을 우선 채택한다"고 정했는데, **구분 수단이 있는지가 미확인**이었다.
있다.

```json
{"ITEM_CODE1":"I61BC","ITEM_NAME1":"실업률","ITEM_CODE2":"I28A","ITEM_NAME2":"원계열",
 "TIME":"202601","DATA_VALUE":"4.1","UNIT_NAME":"%"}
{"ITEM_CODE1":"I61BC","ITEM_NAME1":"실업률","ITEM_CODE2":"I28B","ITEM_NAME2":"계절조정",
 "TIME":"202601","DATA_VALUE":"3",  "UNIT_NAME":"%"}
```

| `ITEM_CODE2` | 의미 |
|---|---|
| **`I28A`** | **원계열** ← 채택 |
| `I28B` | 계절조정 |

**차이가 크다.** 2026-01 실업률이 원계열 4.1% vs 계절조정 3.0%다.

> **확정: `I28A`(원계열)를 쓴다.** §B1.5의 논거 그대로 — 계절조정 시계열은 사후에
> 개정되므로, `available_from_date`를 아무리 정확히 맞춰도 값 자체에 미래 개정이 들어간다.
> 원계열은 개정 폭이 작다.
>
> **계절성은 우리가 처리한다.** 월간 시리즈를 YoY로 변환하면 계절성이 대부분 상쇄되고,
> 그게 §B2 게이트가 요구하는 "실제 모델 입력 형태"이기도 하다.

**구현 요건.** 기존 ECOS 어댑터가 `source_series_key`(통계표코드)만 받는지,
`ITEM_CODE1`/`ITEM_CODE2`까지 지정할 수 있는지 확인해야 한다. **2차원 지정이 안 되면
한 시점에 값이 두 개 오므로 어댑터 확장이 선행**이다.

## 3. vintage 조회 — 지원하지 않는다

ECOS `StatisticSearch`의 인자는 `통계표코드 / 주기 / 시작 / 종료 / 항목코드`뿐이다.
**"몇 년 몇 월 시점에 공표된 값"을 요청하는 파라미터가 없다.**

> **따라서 final-vintage다.** [N6 §3.5](n6_periodic_extras.md)와 같은 종류의 한계이고,
> 대응도 같다 — **한계를 명시하고 원계열을 채택**한다(§2).
>
> 앞으로 쌓이는 데이터에서는 재수집 비교로 개정 폭을 잴 수 있지만,
> **과거 구간에는 소급 적용할 수 없다.**

## 4. ★ 계획에 없던 것 — KSIC 대분류별 취업자

같은 통계표에 **산업별 취업자**가 들어 있고, 분류 체계가 **KSIC 대분류**다.

```
I61BAAA   A 농업, 임업 및 어업(01~03)        201301 ~ 202607
I61BAAB   * 광공업(B,C)                    201301 ~ 202607
I61BAABA  B 광업(05~08)                    201301 ~ 202607
I61BAABB  C 제조업(10~34)                   201301 ~ 202607
I61BAABC  D 전기, 가스, 증기 및 공기조절 공급업(35)  201301 ~ 202607
...
```

**`definitions/industry_groups.py`의 `_SECTION_RANGES`와 같은 체계다.**
괄호 안 숫자가 2자리 KSIC 중분류 범위이고, N2가 만드는 그룹과 직접 매칭된다.

이게 여는 것:

- `11_feature_taxonomy.md` §8.3의 매크로 exposure를 **업종 단위로** 걸 수 있다
- 산업별 고용 증가 → 그 업종 종목의 조건화 변수
- 지금 매크로 조건화 구조가 **0개**라는 점을 감안하면, 조건화를 처음 돌릴 때의
  자연스러운 후보다

**다만 2013-01부터라 표본이 짧고(13년), 우선순위는 여전히 낮다.**
`08` §B1의 "레짐 변수를 늘리는 것보다 조건화를 한 번이라도 돌려보는 게 먼저"는 유지한다.
**수집만 해두고 검정은 나중이다.**
