## 0. 한 줄 결론

**계획대로 진행한다.** 날짜 × 시장 루프가 성립하고, 종가를 포함한 5개 컬럼이 전종목으로 온다.
잠정 결측 방침(`source_close == 0` → 행 결측)이 실측으로 확인됐다.
**계획을 고칠 곳은 두 군데**다 — 휴장일 응답 모양(§3)과 `by_date` 폴백의 종가 부재(§7).

## 2. 시장 인자 — `ALL`을 쓰면 KONEX가 섞인다

2024-01-02 기준이다.

| 호출 | 종목 수 |
|---|---:|
| `market='ALL'` | **2,786** |
| `market='KOSPI'` | 953 |
| `market='KOSDAQ'` | 1,704 |
| KOSPI ∪ KOSDAQ | 2,657 |
| **ALL − (KOSPI ∪ KOSDAQ)** | **129** |
| `get_market_ticker_list(market='KONEX')` | **129** |

**차집합 129건이 KONEX와 정확히 일치한다**(`extra ⊆ KONEX`, 차 0).
KOSPI ∩ KOSDAQ = 0으로 중복도 없다.

> **확정: `ALL`을 쓰지 않는다.** 시장별 호출이 `market` 컬럼을 채우는 유일한 방법이면서,
> 동시에 KONEX 배제 수단이다.

## 3. ★ 휴장일 응답 — 계획을 고쳐야 한다

**빈 응답이 아니다.** 전종목 행이 그대로 오고 **가격 컬럼만 0**이다.

```
get_market_cap_by_ticker('20240101', market='KOSPI')   # 신정
  rows=953  empty=False
  095570: {종가: 0, 시가총액: 0, 거래량: 0, 거래대금: 0, 상장주식수: 45252759}
```

`상장주식수`만 실값이 온다. 그대로 저장하면 **휴장일에 종가 0인 행 2,657개가 매번 쌓인다.**

pykrx 소스(`stock_api.py` 425~429행)를 확인했다.

```python
holiday = (df[["종가", "시가총액", "거래량", "거래대금"]] == 0).all(axis=None)
if holiday and alternative:
    target_date = get_nearest_business_day_in_a_week(date=date, prev=True)
    df = krx.get_market_cap_by_ticker(target_date, market, acending)
return df
```

**`alternative=True`면 휴장일에 전 영업일 데이터를 그 날짜로 반환한다.**
이건 더 나쁘다 — 조용히 날짜가 어긋난 행이 저장된다.

> **확정 방침 두 겹.**
> 1. **`alternative=False`(기본)를 명시적으로 고정한다.** 어댑터에서 인자를 생략하지 않고
>    직접 넘긴다. 나중에 기본값이 바뀌어도 안전하다
> 2. **거래일 캘린더(`infra/calendar/`)로 휴장일을 애초에 호출하지 않는다.** 1차 방어
> 3. 그래도 들어오면 **`source_close == 0` 행 전체 결측** 규칙이 2차 방어

## 4. 결측·0 패턴 — 잠정 방침이 맞았다

정상 거래일 3개 시점, 시장 2개를 봤다.

| 날짜 / 시장 | n | 종가=0 | 거래량=0 | 거래대금=0 | 시총=0 | 상장주식수=0 |
|---|---:|---:|---:|---:|---:|---:|
| 20240102 KOSPI | 953 | **0** | 14 | 14 | 0 | 0 |
| 20240102 KOSDAQ | 1,704 | **0** | 65 | 65 | 0 | 0 |
| 20200331 KOSPI | 915 | **0** | 15 | 15 | 0 | 0 |
| 20200331 KOSDAQ | 1,416 | **0** | 89 | 89 | 0 | 0 |
| 20140602 KOSPI | 907 | **0** | 19 | 19 | 0 | 0 |
| 20140602 KOSDAQ | 1,009 | **0** | 11 | 11 | 0 | 0 |

**정상 거래일에 종가 0은 한 건도 없다.** 0은 거래량·거래대금에만 나타나고 둘이 항상 같이 0이다
(거래정지 종목).

> **확정 결측 정책.**
> - `source_close == 0` → **행 전체를 결측**으로 본다 (휴장일 응답)
> - `source_close > 0` 인데 `volume == 0` / `trading_value == 0` → **진짜 0**(거래정지).
>   NULL로 바꾸지 않는다
> - `listed_shares`는 휴장일에도 실값이 오므로 0 판정에 쓰지 않는다

`02` §3의 잠정 방침을 그대로 채택한다. **일괄 `0 → NULL` 변환은 하지 않는다** — 거래정지일의
진짜 0을 잃는다.

## 5. ★ V1 항등성 — PoC에서 이미 답이 나왔다

`시가총액 == 종가 × 상장주식수`를 종가>0 행 전체에서 검사했다.

| 날짜 / 시장 | 일치 |
|---|---|
| 20240102 KOSPI | **953 / 953** |
| 20240102 KOSDAQ | **1,704 / 1,704** |
| 20200331 KOSPI | **915 / 915** |
| 20200331 KOSDAQ | **1,416 / 1,416** |
| 20140602 KOSPI | **907 / 907** |
| 20140602 KOSDAQ | **1,009 / 1,009** |

**6,904행 전부 정확히 일치한다.** 반올림 오차조차 없다.

**해석.** `시가총액`은 파생값이고 독립 정보가 아니다. 즉 **N1이 실제로 새로 가져오는 것은
`상장주식수`와 `거래대금` 둘**이다. 종가는 미수정 기준이라 `daily_ohlcv.close`(수정)와 다른
정보를 준다.

이 사실이 `02` §7 결정 1(분모 교체 vs variant)에 직접 걸린다 — `fin_log_mcap` 개선의 실체는
**"DART issued_shares 계단형 → KRX 상장주식수 일별"** 하나로 좁혀진다.
V7(`listed_shares` vs DART `issued_shares`)이 개선폭의 상한을 그대로 준다.

## 7. ★ `by_date` 폴백에는 종가가 없다

```
get_market_cap_by_date('20240102','20240131','005930')
  rows=22  cols=['시가총액', '거래량', '거래대금', '상장주식수']
```

**4개 컬럼. 종가가 빠진다.**

> **따라서 `by_date`는 종가 경로가 아니다.** `by_ticker`가 실패했을 때의 폴백으로 쓰면
> `source_close`를 못 채우고 §5의 항등성 검증과 §8의 조정주가 확인이 불가능해진다.
> **폴백은 "결손 날짜 재시도"용으로만 두고, 정상 경로는 `by_ticker` 하나로 간다.**

## 8. ★ 조정주가 확인 — `daily_ohlcv`는 수정주가가 맞다

`02` §6과 `02_feature_candidate.md` §2.3의 미해결 항목이다. **백필 전에 답이 나왔다.**

삼성전자 2018-05-04 액면분할(50:1) 구간을 두 경로로 봤다.

| 날짜 | [A] `get_market_ohlcv_by_date` (naver, adjusted 기본) | [B] `get_market_cap_by_ticker` (KRX 미수정) | 상장주식수 |
|---|---:|---:|---:|
| 2018-04-26 | **52,140** | **2,607,000** | 128,386,494 |
| 2018-04-27 | 53,000 | 2,650,000 | 128,386,494 |
| 2018-05-04 | 51,900 | 51,900 | **6,419,324,700** |
| 2018-05-08 | 52,600 | 52,600 | 6,419,324,700 |

**2,607,000 ÷ 50 = 52,140.** 정확히 일치한다. 상장주식수도 같은 날 정확히 50배로 뛴다.

> **결론: `daily_ohlcv`는 naver 수정주가다. 분할 조정이 제대로 되고 있다.**
> `02_feature_candidate.md` §2.3의 Phase 1 진입 조건은 **이미 충족돼 있었다.**
> 모멘텀·MAX·변동성 피쳐가 미조정 가격 위에 서 있을 가능성은 배제된다.

전 종목·전 구간 검증은 백필 후 V2에서 한다. 여기서 확인한 것은 **조정 메커니즘이 작동한다**는
것이고, 남은 질문은 **어느 종목에서 어긋나는가**다.

## 9. 스로틀 — 여유가 크다

무휴식으로 연속 40회(2024-01-02부터 영업일, KOSPI) 호출했다.

| 항목 | 값 |
|---|---|
| 성공 / 실패 | **40 / 0** |
| 평균 | **0.206s** |
| 최대 | 0.342s |
| 40회 총 | 8.2s |

**6,000회 순수 요청 시간 추정: 약 21분.**

> 다만 **차단 정책이 시간당 누적으로 걸릴 수 있어 40회 성공을 근거로 스로틀을 없애지 않는다.**
> `prices backfill`과 같은 `HumanThrottlePolicy`를 그대로 쓰고, 기본 `--rate-limit-seconds`를
> 보수적으로 둔 뒤 실백필 로그를 보고 조정한다. **야간 배치 + 기존 KRX 잡과 시간대 분리**는
> 그대로 유지한다(exit 75 lock).

## 11. 남은 확인 (백필 후)

PoC로 답할 수 없는 것들이다.

- **V3** `daily_market_cap.volume`(KRX) vs `daily_ohlcv.volume`(naver) 불일치율
- **V4** `listed_shares` 급변일 ↔ `dart_capital_change_raw` 이벤트
- **V5** `종가×거래량` vs 실제 `거래대금` rank 상관 → `px_amihud_20d` 재검정 여부
- **V7** `listed_shares` vs DART `issued_shares` — **`fin_log_mcap` 개선폭의 상한**
- **V8** 시장 이전상장 종목 수 = `stock_master` 조인이 만들었을 룩어헤드 크기
