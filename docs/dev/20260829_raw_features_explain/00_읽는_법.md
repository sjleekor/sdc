  **"이 피처가 무엇을 재고, 왜 그렇게 봤고, 실제로 얼마였나"**를 피처 하나당 문서 하나로 적는다.

## 1. 이 문서 묶음이 존재하는 이유

HTML 보고서는 심사표다. 통과·탈락, 등급, q값을 담고 있다. 그런데 피처를 이해하려면 다른 게
필요하다.

| 질문 | 보고서 | 이 문서 |
|---|---|---|
| 어떻게 계산했나 | 한 줄 요약 | SQL 정본 + NULL 규칙 + warm-up |
| 왜 예측한다고 봤나 | 없음 | 메커니즘·기대부호·근거 문헌 |
| 얼마나 효과가 있었나 | Rank IC 범위 | IC + **5분위 수익률 차이** + 신호 모양 |
| 진짜인가 | 등급 한 글자 | 지연·유동성·생존편향·기간 대조 |
| 어떤 종목이 언제 | 없음 | **아직 없다** (§7) |

`q5_spread_aligned`, `icir`, `onset_h`, `native_ic` 대비 `lag1_ic` 같은 값은 **이미 산출물에
들어 있는데 보고서 화면에 없다.** 이 문서가 그걸 꺼내 온다.

## 3. 각 문서의 공통 구조

피처 문서는 다음 9개 절을 같은 순서로 쓴다.

1. **한 줄 요약** — 이 피처가 무엇이고 이번에 어떻게 나왔나
2. **무엇을 재는가** — 산식 정본, 창, warm-up, NULL 규칙, 변형
3. **왜 예측한다고 봤나** — 메커니즘, 기대 부호, 사전등록 horizon, 한국시장 단서
4. **얼마나 효과가 있었나** — cell별 IC·ICIR·t·5분위 수익률 차이, 신호 모양
5. **진짜인가** — 지연·유동성·생존편향·기간·비중첩 대조
6. **표본과 커버리지**
7. **중복성** — 다른 피처와 같은 정보인가
8. **한계와 확인 못 한 것**
9. **원본 추적** — 이 문서의 숫자를 어디서 다시 뽑는가

## 4. 공통 방법론 — 숫자를 읽기 전에 알아야 할 것

### 4.1 예측 대상 (label)

`research/etl/labels.py`가 만든다.

- `raw_label_{h}d` = **h거래일 뒤까지의 초과수익률**. 같은 `(거래일, 시장)` 안의
  동일가중 평균수익률을 뺀 값이다. 그래서 날짜×시장별 평균이 0에 가깝다.
- `y_rank_{h}d` = 그 초과수익률의 `(거래일, 시장)` 내 백분위 순위 (0~1)
- bucket label `raw_bucket_label_{a}_{b}d` = a일 뒤부터 b일 뒤까지 구간 초과수익률

**시장 중립이지 업종 중립이 아니다.** 그룹이 KOSPI·KOSDAQ 둘뿐이다. 업종 코드가 수집돼 있지
않아서 업종 중립화를 하지 못했다 (`11_feature_taxonomy.md` §1).

### 4.2 Rank IC

`research/etl/metrics.py:57` `per_date_market_rank_ic`.

1. `(거래일, 시장)`마다 피처 값과 `y_rank`의 Spearman 상관을 구한다. 종목 20개 미만인
   횡단면은 버린다 (0으로 채우지 않는다).
2. 같은 날 KOSPI·KOSDAQ 값을 종목 수로 가중평균해 하루치 IC를 만든다.
3. 그 일별 IC의 평균이 `ic_mean`, 표준편차로 나눈 값이 `icir`다.

`t_nw`는 Newey-West 보정 t값이다. 중첩 창 때문에 생기는 자기상관을 보정한다. lag는 누적
horizon이면 `h-1`, bucket이면 `width-1`이다.

**일별 IC 시계열 자체는 저장하지 않는다.** 평균만 남기고 버린다. 그래서 "2021년엔 먹혔고
2023년엔 안 먹혔다"를 직접 보여줄 수 없다 (§7).

### 4.3 5분위 수익률 차이 (`q5_spread`)

`research/etl/metrics.py:200` `per_date_market_quantile_spread`.

**IC를 수익률로 번역한 값이다. 이 문서 묶음에서 가장 중요한 숫자다.**

- `(거래일, 시장)`마다 피처로 종목을 5분위로 나눈다
- 상위 20% 평균 초과수익률 − 하위 20% 평균 초과수익률
- 종목 50개 미만 횡단면은 버린다
- 시장 가중 후 날짜 평균

읽을 때 지켜야 할 네 가지.

1. **단위는 해당 horizon 누적 초과수익률**이다. 연율이 아니다. `cum 0→5`의 0.0038은
   "5거래일 동안 시장 대비 0.38%p"다.
2. **horizon이 다르면 직접 비교하면 안 된다.** 120일짜리 spread가 5일짜리보다 큰 건 당연하다.
3. **거래비용 차감 전**이다. T1/T2 게이트가 쓰는 왕복 60bp 가정이 여기엔 안 들어갔다.
4. **창이 매일 겹친다.** 매일 리밸런싱한 수익률이 아니라 매일 관측한 5분위 차이의 평균이다.
   실제 운용 성과가 아니다.

`q5_spread_aligned`는 기대 부호를 곱해 정렬한 값이다. 기대 부호가 `-`인 피처는 부호를
뒤집었으므로 **양수면 기대대로**다. `q5_spread_raw`가 원래 부호다.

### 4.4 cell — 판정 단위

피처 하나가 아니라 **cell 하나**가 판정 단위다.

```
cell = family × feature × scan_type(cum|bucket) × (h_start, h_end)
```

- `cum 0→20` = 오늘부터 20거래일 뒤까지 누적
- `bucket 20→40` = 20거래일 뒤부터 40거래일 뒤까지 구간만

같은 피처라도 cum 0→5는 통과하고 bucket 20→40은 탈락할 수 있다. 그래서 문서마다 cell을
전부 편다.

### 4.5 세 가지 단계를 섞지 않는다

| 상태 | 뜻 |
|---|---|
| `discovery` | BH 다중검정(q=0.10)을 통과한 cell |
| `screen_pass` | 방향·기간·유동성·지연·강건성 게이트까지 통과 |
| Grade A/B | screening 근거 등급. **모델 채택이 아니다** |
| `validation improved` | 후보 묶음을 모델에 넣었을 때 개선 |

Phase A와 Phase B의 C 등급 뜻이 다르다. A의 C는 탐색·보조·보류, B의 C는 강건성 또는
availability 방향 게이트 실패다.

### 4.6 대조군 — 강건성 판단의 뼈대

같은 cell을 네 좌표에서 다시 계산한다. **정본은 `broad` × `common_survivor` × `native_t`**이고
나머지는 게이트다.

| 축 | 값 | 뜻 |
|---|---|---|
| universe | `broad` | 전 종목 |
| | `tradable` | 20일 평균 거래대금 1억원 이상 + 종가 1,000원 이상 |
| sample_kind | `common_survivor` | 120일 라벨이 끝까지 살아 있는 공통 표본 |
| | `available` | 그 시점에 존재한 모든 종목 (상장폐지 포함) |
| variant | `native_t` | 당일 값 |
| | `lag1` | 직전 유효 세션 값 (하루 늦게 씀) |

- `tradable_retention` = |tradable IC| / |broad IC|. 0.50 미만이면 게이트 실패. 낮으면
  **논문상 알파, 실전 불가**를 뜻한다.
- `lag1_ic` / `native_ic`도 같은 0.50 기준이다. 낮으면 신호가 하루도 못 간다.
- `available_ic`가 `common_survivor_ic`와 부호가 뒤집히면 등급 상한이 C가 된다.

### 4.7 기간 구간

기간 일관성은 다섯 구간으로 본다 (`common` 기준).

`2014_2016` / `2017_2019` / `2020_2021` / `2022_2023_10` / `2023_11_common_end`

`valid_subperiods`가 유효 구간 수, `sign_consistent_subperiods`가 그중 부호가 같았던 구간
수다. 5/5면 전 구간에서 같은 방향이었다는 뜻이다.

### 4.8 표본 경계

- 시작: 2014-06-01
- holdout 시작: 2025-08-01 — **이 이후는 아직 열지 않았다**
- `common_survivor` 표본은 120일 라벨이 필요해 formation이 2025-02-05에서 끝난다

### 4.9 사전등록 horizon이 곧 가설이다

`horizon_scan_config.yaml`의 `primary_horizon_set`은 **결과를 보기 전에 못 박은 값**이다.
"이 메커니즘이 맞다면 이 구간에서 신호가 나야 한다"는 예측 그 자체다.

- 여기 든 cell만 global BH 모집단에 들어간다
- `exploratory_horizon_set`은 진단용이고 BH에 안 들어간다
- 사후에 제일 좋아 보이는 horizon을 골라 대표 성능으로 쓰지 않는다

각 문서 §3에서 **사전등록 밴드와 실제 관측 밴드(`candidate_horizon_band`)를 대조**한다.
이게 가설 검정의 핵심이다.

### 4.10 등급 정의

| 등급 | 뜻 |
|---|---|
| A | screen_pass + 핵심 경고 없음 + 모든 offset 평가 가능 |
| B | screen_pass + 치명적이지 않은 경고 |
| C | 탐색·보조이거나 available 부호 뒤집힘 |
| D | 신호 없음, 부호 반대, 또는 강건성 실패 |

## 5. IC 크기 감각

횡단면 Rank IC는 절대값이 작다. 감을 잡는 기준.

| \|IC\| | 통상 해석 |
|---|---|
| 0.01~0.02 | 약하지만 표본이 크면 유의할 수 있음 |
| 0.03~0.05 | 단일 신호로는 쓸 만한 수준 |
| 0.05~0.10 | 강함. 중복·편향을 먼저 의심 |
| 0.10 이상 | 대개 규모·유동성 같은 구조적 축이거나 look-ahead |

다만 **IC 순위와 수익률 순위는 다르다.** 이번 결과에서도 `px_idio_vol_60d`가 |IC|는 제일
큰데 5분위 차이는 `px_amihud_20d`의 4분의 1이다. 그래서 두 숫자를 항상 같이 본다.

## 7. 이 문서 묶음이 아직 답하지 못하는 것

사용자가 물은 **"어떤 종목이 어떤 시점에 좋은 성과를 보였나"**는 지금 산출물로 답할 수 없다.
빠진 게 둘이다.

**(a) 일자별 IC 시계열.** `per_date_market_rank_ic`가 이미 만들고 있는데 평균만 저장하고
버린다. 저장만 하면 연도별·국면별 성과를 바로 그릴 수 있다. 비용 대비 값이 가장 크다.

**(b) 종목 수준 귀속.** `metrics.py:633` `decile_membership`과 `economic_report`가 이미 있어
상위 10분위 종목·리밸런싱 시점·회전율을 뽑을 수 있다. 다만 HTML 보고서 계획
(`13_feature_performance_html_report_plan.md` §4.2·§8.2)이 종목·날짜 row를 보고서에 넣지
않기로 명시했다. 이 문서 묶음은 `docs/` 안이라 제약이 다르지만, 정책을 정하기 전에는 넣지
않는다.

그때까지 각 문서 §5의 **기간 일관성**과 Phase A의 `subperiod_heatmap.png`가 시점 질문에
답하는 가장 가까운 자료다.

## 9. 35개를 관통하는 것

문서를 다 쓰고 나서 반복해 나타난 것들이다. **개별 문서의 §8(한계)에 흩어져 있는 내용을
여기 모았다.**

### 9.1 IC와 5분위 수익률 차이가 자주 어긋난다

**보고서가 IC만 보여 줬을 때 가장 많이 놓친 것이다.**

| 유형 | 사례 |
|---|---|
| 부호까지 반대 | [20](20_ev_net_share_issuance_yoy.md) IC −0.038 / spread +11.3%p, [30](30_hc_productivity.md) 네 cell 전부, [04](04_px_near_52w_high.md) 여섯 cell 전부, [08](08_px_turnover_shock.md) |
| 크기가 어긋남 | [21](21_ev_payout_yield.md) \|IC\| 0.10 / spread 0.49%p, [06](06_px_idio_vol_60d.md) \|IC\| 1위인데 spread는 4위 |
| 계산 불가 | [31](31_own_amendment_ratio.md) 동점 때문에 NaN |

원인은 **IC가 순위 상관이고 5분위 차이는 양 끝 평균**이라는 데 있다. 극단 분위의 수익률
분포가 치우쳐 있으면 두 지표가 다른 이야기를 한다.

**둘 다 산출하되 어느 쪽을 볼지 목적에 따라 정해야 한다.** 순위를 매기는 모델 입력이면 IC,
분위 롱숏 전략이면 spread다.

**공통 공백: 중앙값 기반 spread나 분위별 평균수익률을 산출하지 않았다.** 이 어긋남을 풀
자료가 없다.

## 10. 다음에 할 일 — 우선순위

문서 35개를 쓰면서 반복해 걸린 공백을 순서대로 적는다.

1. **B×B·A×A 상관을 계산한다** (§9.2, §9.3). 지금 상태로는 35개 중 몇 개가 독립된
   발견인지 말할 수 없다. **가장 시급하다.**
2. **분위별 평균수익률과 중앙값 spread를 산출한다** (§9.1). IC와 5분위 차이의 어긋남을
   풀 유일한 자료다.
3. **규모를 통제한 증분 IC를 잰다** (§9.4). `|ρ| = 0.75`가 미해결이다.
4. **일별 IC 시계열을 저장한다** (§7). `per_date_market_rank_ic`가 이미 만들고 있는데
   평균만 남기고 버린다. **"어느 기간에 작동했나"에 답할 수 있게 된다.**
5. **반대 방향이 안정적인 셋을 새 config로 재등록한다** (§9.6).
6. **`fin_sue`의 XBRL 백필 대상을 고른다** ([22](22_fin_sue.md) §11).
7. **업종 코드를 수집한다** (§9.8). 가장 크고 가장 오래 걸리는 작업이다.
